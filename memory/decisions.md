[2026-08-13] Decision: push directly to main; no feature branches or PRs — Reason: hobby project, and Vercel auto-deploys from main. The cc-rig `block-main` hook is unregistered in .claude/settings.json (script kept on disk so it is a one-line revert). Note PRs #1-52 in earlier session logs predate this.
[2026-08-13] Decision: gate `images.unoptimized` to development rather than converting card art to raw <img> or dropping next/image — Reason: keeps Vercel's image optimization in production, where it works, while sidestepping Scryfall's User-Agent block locally. Two lines, no component changes.
[2026-08-13] Decision: `.claude/skills/project-patterns` is the authority on conventions, over agent_docs/conventions.md — Reason: conventions.md claims kebab-case component files but the tree has always used PascalCase; project-patterns was written from the actual tree.
[2026-08-13] Decision: gh + supabase installed as user-local binaries in ~/.local/bin rather than via Homebrew — Reason: Homebrew was absent and its installer needs sudo, which could not run unattended. Homebrew is now installed, so these can be migrated to `brew install gh supabase/tap/supabase` whenever convenient; upgrades are manual re-downloads until then.
[2026-08-13] Decision: fuzzy card-name matches are shown for review (`≈ N close matches`, typed → matched), never applied silently — Reason: trigram scoring cannot separate near-identical card names. Against "Llanowar Elf", both "Llanowar Elves" and "Llanowar Elite" score 0.647 while bare "Llanowar" scores 0.692 — auto-applying would put the wrong card in a deck and look like it worked.
[2026-08-13] Decision: fuzzy lookup runs only on names exact matching already missed, capped and batched — Reason: fuzzy is ~10x the cost of equality. Putting it in the main path would recreate the statement-timeout failure migration 017 exists to remove.
[2026-08-13] Decision: `/api/cards/lookup` keeps its legacy bare-array response by default; the `{cards, fuzzy}` shape is opt-in via `{ fuzzy: true }` — Reason: collection import consumes the same endpoint and needed no change, keeping the fix to two app files.
[2026-08-13] Decision: the browsable card pool is defined by card type + set type in the cards_playable materialized view, never by format legality — Reason: unreleased cards carry legality rows that are all `not_legal`, so a legality filter deletes exactly the upcoming sets players want (Marvel Super Heroes had 133 cards, 6 "legal"). Every card has legality rows, so "no rows" is not a preview signal either; use sets.released_at.
[2026-08-13] Decision: default card-browser sort is newest-set-first, not (cmc, name) — Reason: alphabetical-within-cost put a blank placeholder land and nine World Championship advertisements on page one. Newest-first opens on what players are brewing with. cmc and name remain available via p_sort.
[2026-08-13] Decision: cards_playable is refreshed by the sync rather than being a plain view or a trigger — Reason: card data only changes on sync, so a ~16s CONCURRENTLY rebuild once per sync buys a 20x faster browse and removes the statement-timeout failure entirely.
[2026-08-13] Decision: the Scryfall sync runs from GitHub Actions, not Vercel cron — Reason: a full sync measured 7m16s and Vercel Hobby caps functions at 60s regardless of `maxDuration = 300`. Actions has no cap, is free, and already holds repo secrets. Daily 06:20 UTC plus workflow_dispatch, with a concurrency group so a manual run cannot overlap a scheduled one.
[2026-08-13] Decision: the deck editor's default filter is the deck's own format, not Arena — Reason: PR #43 turned the Arena filter off there deliberately, and an Arena default hides the paper cards in a Commander deck (the Trostani deck has several). The standalone /cards browser defaults to Arena since that is the app's purpose.
[2026-08-13] Decision: default filter chips render above the results grid, not inside the collapsed Filters panel — Reason: a default that silently removes cards is worse than no default. Session 17 was spent chasing exactly that class of invisible cause; the chip makes it self-explaining and one click to clear.
[2026-08-13] Decision: the default browse anchors on the current set — the newest expansion/core set releasing within 14 days — with unreleased sets sorted last, rather than plain `released_at DESC` — Reason: sorting by the newest set Scryfall knows about opened the browser on cards three months from release. The 14-day window covers prerelease weekend and Arena's early drop, which is what makes The Hobbit current on 2026-08-13 rather than Marvel Universe. Re-evaluated on every sync, so it never needs editing.
[2026-08-13] Decision: legality for spoiled-but-unreleased sets is presumed from the set's product type, not passed through blanket — Reason: migration 018 let any unreleased card satisfy any format filter, so Star Trek Commander precon cards appeared in Standard searches. Expansion/core presume Standard-and-below; commander/eternal/masters presume Commander and the eternal formats only; Arena formats additionally require available_on_arena; pauper keys off rarity. Real legality rows always win, so the presumption evaporates as each set releases.
[2026-08-13] Decision: `cards_playable` prefers a released printing when choosing the one row per card — Reason: the previous preference took the newest printing, so a card reprinted in The Hobbit would be filed under its Star Trek printing and sort to the bottom of the browse despite being playable tomorrow.
[2026-08-13] Decision: the deck editor's persistence is swapped behind a `DeckStore` rather than forking DeckEditor for the Stateless Deck Builder — Reason: DeckEditor is ~1,600 lines and already kept the whole deck (card names, images, costs) in local state with saving as fire-and-forget, so only 7 call sites actually touched the API. A fork would have duplicated every future fix. The API store writes deltas and ignores `persist`; the local store ignores the deltas and writes a snapshot from an effect, so stored state is always exactly rendered state.
[2026-08-13] Decision: DeckEditor takes `mode: "api" | "local"` and builds the store itself, rather than receiving a store object — Reason: /decks/[id] is a Server Component and functions cannot cross the RSC boundary. The store is built client-side in a useMemo, which also keeps the snapshot effect from re-firing every render.
[2026-08-13] Decision: stateless decks live in localStorage, not a cookie — Reason: a 100-card deck carries its card display data so the editor can render without a round trip, which lands around 25KB against a cookie's 4KB ceiling. Nothing is sent to the server, so a cookie would buy nothing anyway.
