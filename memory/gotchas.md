# Gotchas (git-tracked, shared)

Known issues, things that did not work, and surprises. One line per entry.

Format: `[YYYY-MM-DD] Gotcha: <what happened> — Fix: <what worked>`

<!-- Entries below -->

[2026-08-13] Gotcha: Scryfall's CDN returns 400 "Your User-Agent header is currently set to default or generic value" to Next's server-side image optimizer, so every next/image card thumbnail breaks under `next dev`. remotePatterns was never the problem. Vercel's optimizer sends an accepted UA so production is fine — Fix: `images.unoptimized: process.env.NODE_ENV === "development"` in next.config.ts. Note `next start` locally still breaks (NODE_ENV=production).
[2026-08-13] Gotcha: the typecheck commit-gate hook ran `npx tsc --noEmit` at the repo root, but there is no root tsconfig.json — tsc printed its help banner and exited 0, so every commit passed the gate regardless of type errors. Silently fail-open since init — Fix: hooks now run `pnpm typecheck` / `pnpm lint`; verified exit 2 on a planted type error.
[2026-08-13] Gotcha: cc-rig generates `.mcp.json` pointing at `@anthropic/mcp-playwright`, which does not exist on npm (404) — the Playwright MCP has never worked in any cc-rig project here, incl. GreatBanquet-Site — Fix: empty the repo-level mcpServers and let the `playwright` plugin supply `npx @playwright/mcp@latest`.
[2026-08-13] Gotcha: Node Playwright and Python Playwright pin different chromium revisions (1234 vs 1223). Installing browsers for one leaves the other failing with "please run playwright install" — Fix: run both `npx playwright install chromium` and `python3 -m playwright install chromium`.
[2026-08-13] Gotcha: hardening SECURITY DEFINER functions with `search_path = public` alone breaks card search — pg_trgm and uuid-ossp live in Supabase's `extensions` schema, so the trgm operators fall out of scope — Fix: pin to `public, extensions, pg_temp` (see migration 016).
[2026-08-13] Gotcha: the first Supabase query after the project sits idle can fail with "canceling statement due to statement timeout" — cold start, not a broken query or RLS problem — Fix: just retry; subsequent calls settle to ~500ms.
[2026-08-13] Gotcha: `vercel link` writes `.vercel/project.json` into the _current_ directory. Running it from `~` silently links your home folder and the repo still reports unlinked — Fix: run it from the repo root, or move the stray `~/.vercel` in. CLI auth lives separately in `~/Library/Application Support/com.vercel.cli`, so moving the folder is safe.
[2026-08-13] Gotcha: `cards_name_trgm_idx` is a GIN trigram index — it serves fuzzy `%` matching, NOT equality. There was no index on `lower(name)` at all, so every exact-name lookup seq-scanned ~114k rows. Deck import died on it: 470ms warm, 5,449ms cold, past the statement_timeout Supabase pins per role (anon 3s, authenticated 8s) — Fix: migration 017 adds `cards(lower(name))` + a partial index on the DFC front face. 20ms warm after.
[2026-08-13] Gotcha: `col = ANY(SELECT lower(unnest(p_arr)))` plans as a hashed SubPlan filter over a seq scan and can NEVER drive an index scan, no matter what indexes exist. Same for OR-ing two different expressions in one WHERE — the planner can use at most one index and in practice uses neither — Fix: make the array a CTE that drives a nested-loop join, and UNION ALL the branches instead of OR-ing them (see migration 017).
[2026-08-13] Gotcha: Supabase does not grant permission for `ALTER FUNCTION ... SET pg_trgm.similarity_threshold` (42501). pg_trgm's `set_limit()` works fine from `authenticated` though — Fix: call `set_limit()` inside a plpgsql function, capturing `show_limit()` first and restoring it before returning. PostgREST pools connections, so an unrestored value silently retunes every later `%` query on that connection.
[2026-08-13] Gotcha: a route that returns `[]` on a database error makes a failed query indistinguishable from "no rows matched". This is exactly how a 5s query timeout surfaced to the user as "88 cards not found" — Fix: return a non-200 with a message and let the UI say "lookup failed". Prefer this over silent degradation anywhere a caller renders the empty case as a real answer.
[2026-08-13] Gotcha: `supabase link` writes `supabase/.temp/` into the repo, including `pooler-url` which can carry connection credentials — Fix: it is now in .gitignore. Don't commit it.
[2026-08-13] Gotcha: `search_cards` does `DISTINCT ON (oracle_id)` across all 114,546 printings and sorts all 37,598 distinct cards by (cmc, name) before LIMIT/OFFSET — an unfiltered browse touches ~116k shared buffers on a 226MB table. Warm ~215ms, cold 11.3s → cancelled by the statement timeout. No index fixes it; the dedup+re-sort must materialise the whole catalogue before it can page — Fix (partial): retry in the route. Real fix (open): materialized view of one row per oracle_id indexed on (cmc, name), refreshed after the Scryfall sync.
[2026-08-13] Gotcha: `/api/cards/sets` returns `{ error }` on failure but both consumers rendered `sets.filter(...)`, so any sets failure crashed the whole page with "sets.filter is not a function" rather than degrading — Fix: `Array.isArray(data) ? data : []` at both call sites. Worth auditing any other route whose success shape is an array but whose error shape is an object.
[2026-08-13] Gotcha: Scryfall changed the /bulk-data schema — `download_uri` (JSON array) became `jsonl_download_uri` (gzipped JSONL), and `size` became `compressed_size`. Our sync read the old field, passed undefined to fetch(), and threw on every run; the daily Vercel cron failed silently for ten weeks and no card was written after 2026-06-05 — Fix: read jsonl_download_uri, gunzip + readline + JSON.parse per line, and validate the field up front so the next rename fails loudly instead of no-op'ing.
[2026-08-13] Gotcha: the card upsert included `set_type`, which does not exist on `cards` (migration 007 was never applied to production). PostgREST rejects the entire batch on an unknown column, and the script only console.error'd — so a sync could report "Done. N cards synced" having written nothing. The `object[]` typing on the batch arrays hid it from tsc — Fix: dropped set_type from both card upserts. Never add a column to those batches without confirming it exists in information_schema first.
[2026-08-13] Gotcha: Vercel Hobby caps function duration at 60s regardless of `export const maxDuration = 300`. The Scryfall sync route cannot complete there no matter what the code says — Fix (interim): run `pnpm sync:cards` locally. Scheduling alternatives (GitHub Actions) tracked in todo.md.
[2026-08-13] Gotcha: filtering the card pool by "legal in a supported format" deletes new sets — unreleased cards carry legality rows that are all `not_legal`, so Marvel Super Heroes had 133 cards but only 6 "legal". Note this was itself amplified by the stale sync — Fix: filter the browsable pool by card type + set type, not legality. Every card has legality rows, so "no rows" is not a usable preview signal either; use sets.released_at.
[2026-08-13] Gotcha: with one-row-per-card in cards_playable, filtering by the chosen printing's `set_code` silently drops reprints whose preferred printing lives in another set — 24% of Lord of the Rings and 17% of M21 missing, and every basic land vanishing from a new set because a newer set outranked it — Fix: the view carries `set_codes[]` (every eligible set the card appears in) with a GIN index, and search filters with `&&` overlap.
[2026-08-13] Gotcha: `ORDER BY CASE WHEN p_sort = 'x' THEN col END` cannot use an index — the planner seq-scans and sorts the whole view (45ms vs 3.5ms) — Fix: plpgsql with a dynamic ORDER BY chosen from a fixed whitelist, values still bound via USING.
[2026-08-13] Gotcha: `ALTER FUNCTION ... SET statement_timeout` does not let a long function outrun the timeout. Verified: the setting attaches (visible in pg_proc.proconfig) but Postgres arms the timer at statement start, so REFRESH CONCURRENTLY (~16s) still got cancelled — Fix: raise it on the role before the call (`ALTER ROLE service_role SET statement_timeout`), and put the fast-fail back where it matters with an AbortSignal on the user-facing RPC.
[2026-08-13] Gotcha: `Cache-Control: public, s-maxage=3600` with no `max-age` gives browsers no directive, so they cache heuristically and keep serving the pre-sync catalogue until a hard reload — the API was verifiably correct while the page showed old cards — Fix: add `max-age=0` so browsers revalidate while the CDN still caches.
[2026-08-13] Gotcha: tsx transpiles scripts/ to CJS, so top-level await fails with "Top-level await is currently not supported with the cjs output format" — Fix: use the main()/catch shape, as sync-scryfall.ts does.
[2026-08-13] Gotcha: `released_at DESC` sorts by the newest set Scryfall _knows about_, not the newest set anyone can play — on 2026-08-13 page one was Star Trek (2026-11-13) and Reality Fracture (2026-10-02) while The Hobbit was releasing the next day — Fix: migration 019 anchors the browse on `current_set_release_date()`, the newest expansion/core set releasing within 14 days, and sorts unreleased sets last. The 14-day window is deliberate: Scryfall only publishes the paper date, but prerelease runs ~9 days early and the Arena drop ~3 days early.
[2026-08-13] Gotcha: Scryfall marks every format `not_legal` until a set actually releases — verified Star Trek and Reality Fracture `not_legal` across all 11 formats while The Hobbit already had real data a day before release. Migration 018 worked around it by letting any unreleased card pass any format filter, which put Star Trek Commander precon cards in a Standard search — Fix: `presumed_format_legality(set_type, on_arena, rarity, format)` in migration 019 infers from the product type instead; real legality rows always win. Arena-only formats (alchemy/historic/brawl/timeless) additionally require `available_on_arena`.
[2026-08-13] Gotcha: `sets.available_on_arena` was read from whichever printing streamed first, and Scryfall's bulk file is ordered by collector number so that is usually a paper-only showcase — The Hobbit was recorded as not-on-Arena while 241 of its 321 cards were — Fix: OR the flag across every card in the set during pass 1 of the sync.
[2026-08-13] Gotcha: right after a migration DROPs and re-CREATEs an RPC, the first request can still be served by a pooled PostgREST connection holding the pre-migration plan — one `/api/cards/search` call returned the old sort order while a curl seconds earlier and 12 calls seconds later all returned the new one — Fix: nothing to do, it clears as connections cycle. Do not chase it as a caching bug; re-request before believing a post-migration result.
[2026-08-13] Gotcha: the sync route's GET handler ran a full sync with no auth, commented "no auth needed, Vercel signs cron requests". Vercel only sends an Authorization header when CRON_SECRET is configured, and the handler never checked one anyway — any anonymous request to /api/sync/scryfall could start a sync — Fix: GET deleted with the cron. If a cron-style endpoint is ever added back, set CRON_SECRET and verify it in the handler; do not assume the platform authenticates for you.
[2026-08-13] Gotcha: `lookup_cards_by_set_collector` declared RETURNS TABLE (... type_line, rarity ...) but selected (... rarity, type_line ...). Postgres matches positionally, so every caller got them swapped — verified in production: (hob, 1) returned rarity 'Creature — Dog' and type_line 'common'. Any decklist imported with "(SET) collector" lines got a garbage type line, silently breaking type grouping, the mana curve's land exclusion, and commander detection. It also filtered on `c.set_type`, which does not exist on `cards` — Fix: migration 020 rewrites it, joining `sets` for the set-type filter. When adding a column to an RPC, check the SELECT order against RETURNS TABLE — Postgres will not warn you.
[2026-08-13] Gotcha: `colors` and `color_identity` are different things and Commander/Brawl rules use identity — a card costing {2} with a "{B}:" ability is colours {} and identity {B}. Filtering a Commander pool by `colors` offers cards MTGA will reject — Fix: migration 021 adds `p_color_identity` to search_cards as its own parameter rather than overloading p_colors, which still means "cards I can cast".
[2026-08-13] Gotcha: after a migration adds a column to a search RPC, the browser and Vercel's CDN can keep serving pre-migration responses — `Cache-Control: public, s-maxage=3600, max-age=0` lets the CDN hold a cached body for an hour. Cost real confusion mid-session: the commander colour chip did not appear because the page's search results predated the migration, while a fresh fetch on the same page returned the new field — Fix: hard-reload when verifying, and expect up to an hour of stale shapes in production after a deploy that changes a cached response's shape.
